# Anna Karenina Reception Map

Небольшой DH-проект для заявки в магистратуру: рецептивная карта романа Л. Н. Толстого "Анна Каренина" и экранизации Александра Зархи.

## Идея

Проект проверяет не то, "понравился ли роман или фильм", а какие элементы канона становятся заметными в пользовательских высказываниях:

- персонажи;
- сюжетные узлы;
- конфликты;
- моральные оценки;
- адаптационные претензии;
- актёрская игра, кастинг и визуальный стиль фильма.

Для проекта "Слово Толстого" это можно представить как дополнительный слой: пользователь видит не только текст романа, но и карту того, какие элементы "Анны Карениной" продолжают жить в читательской и зрительской рецепции.

## Минимальный результат

Практический результат проекта:

- открытая методология разметки;
- две основные таблицы данных: `reviews.csv` и `mentions.csv`;
- справочник меток `codebook.csv`;
- статический дашборд в `docs/`, который можно открыть через GitHub Pages.

Дашборд не требует базы данных или сервера. Он читает CSV-файлы из папки `docs/data/` и строит простые сводки в браузере.

## Состояние MVP

В пилотной версии размечены 24 отзыва: 12 о романе из LiveLib и 12 об экранизации Александра Зархи с Кинопоиска. Из них выделено 80 смысловых упоминаний.

Интерфейс показывает:

- первый исследовательский маршрут о Левине как втором центре романа и зоне потерь экранизации;
- обзорную карту совместной встречаемости рамки и персонажа в размеченных упоминаниях;
- главный зеркальный график `Роман <-> общий узел <-> Фильм`, который не смешивает две выборки;
- внутренний сегмент `adaptation_loss` в кино-полосе, подсвечивающий место расхождения;
- толщину ребра как число совместных упоминаний;
- интерактивную proof card с короткими доказательными резюме и confidence;
- компактные фильтры по объекту, рамке, тону и текстовому поиску.

### Предварительные выводы

- В книжной части 10 из 35 упоминаний кодируются рамкой `levin_as_alternative_center`: пилот поддерживает чтение романа как двойной конструкции `Анна — Левин`.
- Среди восьми явно левинских киноупоминаний пять относятся к адаптационным потерям, два — к кастингу и одно — к актёрской игре.
- Первый маршрут MVP: в пилотной выборке линия Левина особенно заметна как второй центр романа, а в киноотзывах — через ощущение адаптационной утраты.

Визуальный принцип MVP — не добавлять ещё один график, а выделять внутри общего внимания место расхождения. Поэтому пять упоминаний об адаптационной потере показаны как отдельный цветовой слой внутри восьми киноупоминаний Левина.

Эти частоты описывают только аналитически отобранную пилотную выборку и не являются рейтингом романа, фильма или мнением всей аудитории. Книжные и киноотзывы — две независимые группы текстов: общие узлы показывают пересечение внимания к персонажам, но не доказывают причинный переход от одной рецепции к другой.

## Данные

Основные данные для публичного дашборда:

- `docs/data/reviews.csv` - одна строка на один отзыв;
- `docs/data/mentions.csv` - одна строка на одно смысловое упоминание внутри отзыва;
- `docs/data/codebook.csv` - справочник меток и правил разметки.
- `docs/data/review_texts.json` - полные оригинальные тексты 24 выбранных публичных отзывов для вкладки «Отзывы».

По решению проекта дашборд публикует полные тексты выбранной пилотной выборки в отдельной вкладке «Отзывы». Исследовательские графики по-прежнему используют короткие `evidence_short`, чтобы не перегружать основной экран.

## Локальный архив доказательств

Для ручной проверки саммаризации создан каталог `local_evidence/`. Он не входит в `docs`, исключён из Git и содержит:

- побайтовые копии двух исходных `.txt` с SHA-256;
- индекс по авторам, датам, рейтингам и лайкам;
- 24 отдельные карточки с полным оригинальным отзывом и текущей разметкой;
- один сводный файл со всеми выбранными отзывами.

Точка входа: `local_evidence/formatted/index.md`. Пересборка:

```powershell
python tools\build_local_evidence.py
```

## GitHub Pages

После загрузки проекта на GitHub можно включить GitHub Pages:

1. Settings -> Pages.
2. Source: branch `main`.
3. Folder: `/docs`.
4. Открыть опубликованную ссылку.

Проверяющий сможет увидеть методологию, CSV-данные и интерактивный дашборд.

Для локального просмотра из любой папки:

```powershell
python -m http.server 8000 --directory "C:\ag_work\pet_project\agent-writing-workbench\ITMO\anna-karenina-reception-map\docs"
```

После запуска открыть `http://localhost:8000`.

## Исследовательская формула

Сенаторова показывает, как можно количественно анализировать речь персонажей в экранизации. Этот проект добавляет другой слой: не как распределена речь внутри фильма, а какие элементы романа и фильма становятся заметными в публичных читательских и зрительских интерпретациях.
